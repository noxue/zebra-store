# 执行计划

## 项目目标

构建一套可独立部署的数字商品交易系统：

- **backend**：Rust + axum + sea-orm，默认 SQLite，改配置即可切换 MySQL / PostgreSQL
- **storefront**：用户商店前台（Vue3 + TSX，二次元风格）
- **admin**：管理后台（Vue3 + TSX，二次元风格），站点名 / Logo / 主题等可在后台自定义

系统提供稳定的 API 契约（路径、字段、信封、错误码）、完整的商店与管理功能，
并通过独立适配器兼容常用发卡站协议。页面与交互以 `docs/reference/*-spec.md` 为验收依据。

## 前期调研结论

- 兼容性参考服务已在本地跑通，并写入了示例数据
  （分类、商品、SKU、卡密、支付渠道、Banner、文章、会员等级、优惠券、活动价、礼品卡、用户、订单）
- 截图：用户前台 28 页（游客 18、会员 10）、管理后台 58 页、暗色 2 页，共 88 张，存于 `docs/reference/screenshots/`
- 三份规格文档：后端（约 60 张表、约 330 个路由、业务流程、10 种支付网关、20 个设置 key、16 类后台任务）、前台、后台

## 关键设计决策

| 问题 | 决策 | 理由 |
|---|---|---|
| 分层 | 7 个 crate：shared / domain / app / infra / migration / api / server | 依赖方向由 Cargo 强制，并由架构测试验证 |
| 多数据库 | sea-orm + sqlx 三个驱动特性全开；迁移只用 SchemaBuilder | 运行时按 URL scheme 选择驱动，只改配置即可切换 |
| 任务队列 | **基于数据库的任务表 + tokio worker** | 默认无需 Redis，减少部署依赖 |
| 缓存 / 限流 | 默认进程内（moka + 自研令牌桶），可选开启 Redis | 单机开箱即用，也支持扩展部署 |
| RBAC | casbin-rs（keyMatch2 + role 继承），策略存 `casbin_rule` 表 | 权限 key 统一为 `METHOD:/admin/...` |
| 金额 | rust_decimal，序列化为两位小数字符串 | 避免浮点误差并保持接口格式稳定 |
| 加密 | AES-256-GCM（key = sha256(secret)，hex(nonce‖ct)）、HMAC-SHA256 签名 | 支持安全存储及供应商协议签名 |
| 前端 | 两个独立 Vite 项目，TSX；Tailwind v4 + 自研二次元组件库 | 按要求一共三个项目，前端之间不共享包 |
| 主题可配置 | `site_config.brand`（名称 / Logo / 图标）+ `site_config.theme`（主色、强调色、背景图、看板娘图、动效开关） | 支持后台完整配置品牌和视觉风格 |

## 开发阶段（按依赖顺序，一次性全量完成）

1. **M0 基础设施**：workspace、lint、配置、日志、数据库连接、迁移框架、响应信封、i18n 消息、错误体系、健康检查；两个前端项目脚手架 + 二次元设计系统 + API 客户端
2. **M1 身份与权限**：管理员 / 用户 JWT、登录与限流、TOTP 两步验证 + 恢复码、Casbin RBAC + 内置角色、权限目录、审计日志、验证码（图形 / Turnstile）、邮件验证码、合规确认
3. **M2 设置与内容**：settings key-value 与 20 个设置 key、`/public/config`、上传与素材库、分类、文章 / 文章分类、Banner、导航 / 关于 / 法律 / 公告
4. **M3 商品目录**：商品、SKU、批发价、会员价、库存策略、人工表单 schema、卡密（批次、导入、导出）、公开商品接口
5. **M4 交易核心**：购物车、定价引擎（活动价 / 批发价 / 会员价 / 优惠券）、订单（父子单、状态机、风控）、支付渠道与 10 种网关、回调、钱包支付、任务队列（超时取消）、自动 / 人工发货、退款、订单邮件
6. **M5 用户资产**：钱包与充值、礼品卡、会员等级自动升级、推广返利（点击、佣金、提现）
7. **M6 分销商**：申请审核、域名（子域名 / 自定义）、租户中间件、站点配置、商品加价、分润账本、结算、提现
8. **M7 对接**：API 凭证、上游 API（本站做供货方）、站点连接 + 商品映射 + 同步 + 采购单 + 下游回调 + 对账
9. **M8 Telegram 与通知**：通知中心（邮件 / Telegram / 飞书）、Channel API、Bot 配置、群发、Telegram / Google 登录与绑定
10. **M9 仪表盘与杂项**：仪表盘统计、趋势、排行、库存告警、登录日志、sitemap / robots、系统版本
11. **M10 用户前台 UI**：全部页面（见 storefront-spec §2 路由表）
12. **M11 管理后台 UI**：全部页面（见 admin-spec §2 菜单表）
13. **M12 联调与验收**：契约比对、E2E、三种数据库验证、截图对比、打包部署文档

> 实际执行时后端与前端交叉进行：每完成一组后端 API，就实现对应前台 / 后台页面并联调。

## 验证策略

- **单元测试**：domain 的定价、状态机、优惠、签名、加密（包含跨语言兼容测试向量）
- **集成测试**：`zs-api/tests/*`，内存 SQLite，覆盖每个路由组的主要路径
- **契约比对**：`scripts/contract-diff`，对参考服务（:8080）和本项目（:8081）发送相同请求，
  对比 JSON 结构（字段名与类型），差异即缺陷
- **E2E**：Playwright 跑通游客下单 → 模拟支付回调 → 自动发卡 → 查单；会员下单、充值、礼品卡；后台增删改查
- **多数据库**：同一套集成测试分别跑 SQLite / MySQL / PostgreSQL（Docker 可用时；本机 Docker 目前 I/O 报错）
- **UI**：Playwright 按验收路由截图，人工逐页检查信息结构
