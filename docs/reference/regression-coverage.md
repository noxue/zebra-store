## 本次发现并修复的缺陷

1. **MISC-01**：`Config::validate` 未拒绝 `config.example.yml` 中的 `change-me-*` 示例密钥（长度 ≥16 即通过），按示例配置即可带默认密钥启动；重复密钥错误不指明是哪两项。修复：`crates/app/src/config.rs` 拒绝 `change-me` 前缀，重复检测 trim 后逐对比较并报出两个键名。
2. **RISK-01**：`server.trusted_proxies` 配成 `0.0.0.0/0`/`::/0` 会信任所有来源的 `X-Forwarded-For`（风控/限流可被伪造 IP 绕过），非法条目被静默丢弃。修复：`Config::validate` 拒绝 `/0`、越界前缀与非 IP/CIDR 条目（启动失败）。
3. **FE-06**：主站 `nav_config.custom_items` 只做长度/枚举归一化，`javascript:alert(1)` 外链与 `//evil.com` 站内链接会被保存并渲染为 `<a href>`（存储型 XSS）。修复：`crates/domain/src/settings/schema/site.rs::normalize_nav` 丢弃非 `http(s)://` 外链和非站内路径；storefront `useNavConfig` 经 `utils/navUrl.ts::isSafeNavUrl` 二次过滤。
4. **NTF-02**（后续补测发现）：验证码/换绑邮件完全不带站点品牌，分销站点用户收到的邮件既无分销站点名也无网址；分销订单状态邮件只用域名，忽略分销站点名与客服邮箱（Reply-To）。修复：`MailBrandResolver` 按请求租户/订单分销商解析品牌，主题前缀、正文站点与网址、From 名、Reply-To 全链路应用，分销作用域永不回退主站品牌。
5. **NTF-03**（后续补测发现）：lettre 默认优先 AUTH PLAIN，Message-ID 域名取本机主机名。修复：统一 SMTP 传输（LOGIN 优先）与 `<hex@发件域名>` Message-ID + Date。
6. **MISC-01 剩余部分**：`axum::serve` 无读头/空闲/头大小限制。改为 hyper-util auto Builder（HTTP/1 header_read_timeout 10s、max_buf_size 1MB+4KB、HTTP/2 max_header_list_size 1MB、连接 120s 无读写即关闭、优雅停机）。注：hyper 的读头超时也覆盖 keep-alive 等待下一请求的时段，空闲 HTTP/1 连接 10s 即关闭（比原项目 120s 更严格）。
7. **绑定校验（contract-diff B2 后续）**：`POST /guest/payments` 先校验游客凭据再解析请求体，与原项目（先 ShouldBindJSON）顺序相反；已改为先绑定。
