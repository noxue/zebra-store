# 卡密转换器

卡密转换器适合“上游交付的卡密不能直接给买家，必须交给自己的程序验证或导入，再返回自有系统卡密”的场景。一个连接代表一个第三方程序，可以被多个商品和 SKU 使用；没有绑定转换器的商品继续按原方式发货。

## 配置转换程序

在后台打开 **对接管理 → 卡密转换器**，添加程序名称、公开 HTTPS 地址和专用认证 Token。这个 Token 应只允许读取类型、健康探测和执行卡密转换，不要填写管理员或高权限 API Token。保存后运行连接测试并刷新类型；程序返回的类型 ID 和字段定义会自动显示。

转换端需要实现版本化 HTTP 接口、类型发现和转换请求。开发前请阅读[卡密转换器协议 v1](./card-converter-protocol)。协议内有请求/响应样例、错误码、变量、数量校验、认证和幂等要求。

## 绑定商品和类型

在同一个页面的商品绑定区域选择商品/SKU、转换程序以及该程序返回的类型。选择器会显示本地商品或其上游映射来源，方便管理员核对。为当前类型填写程序要求的参数，并按需配置 `extra` 常量和受限变量，例如 `&#123;&#123;site.domain&#125;&#125;`、`&#123;&#123;product.title&#125;&#125;`。邮箱、手机号等个人信息默认不会传递。

商品只要配置了绑定，自动发货和上游自动卡密交付就会先调用转换器；未配置的商品走原有交付流程。管理员手动发货时，如果输入的是逐行卡密且数量与订单一致，也会调用转换器；上游返回的人工处理说明不会被当作卡密转换。手动导入卡密不需要标注来源。转换结果是买家页面、下游供货接口、邮件和 Webhook 共用的正式交付内容。

## 失败与恢复

转换器调用失败时，订单保持处理中，不会把上游卡密交给买家。上游采购已经成功时，系统会保存其原始交付供内部重试，后续只重试转换，不会再次向上游采购。本地库存商品会固定本次使用的卡密；重试不会再扣另一批库存。

健康任务每分钟检查启用中的转换器。连续探测失败达到阈值会记录事件并通知管理员 Telegram；恢复时会记录恢复事件并唤醒挂起转换。全部卡密转换成功后，系统才完成订单并通知买家。类型错误、幂等冲突或修复配置后仍失败的订单，可在采购单页面使用“重试卡密转换”，此操作不会重新采购。后台首页会显示异常转换器名称、最近错误和影响商品数；转换事件日志不记录 Token 或卡密明文。

协议、健康探测和订单恢复的开发细节见[协议文档](./card-converter-protocol)。
