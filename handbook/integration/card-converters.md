# 卡密转换器

卡密转换器适合“上游交付的卡密不能直接给买家，必须交给自己的程序验证或导入，再返回自有系统卡密”的场景。一个连接代表一个第三方程序，可以被多个商品和 SKU 使用；没有绑定转换器的商品继续按原方式发货。

## 配置转换程序

在后台打开 **对接管理 → 卡密转换器**，添加程序名称、公开 HTTPS 地址和专用认证 Token。这个 Token 应只允许健康探测和执行卡密转换，不要填写管理员或高权限 API Token。保存后运行连接测试。

转换端需要实现健康探测和转换请求。开发前请阅读[卡密转换器协议](./card-converter-protocol)。协议内有请求/响应样例、错误码、变量、数量校验、认证和幂等要求。

## 绑定商品和转换器

在同一个页面的商品绑定区域选择商品/SKU 和转换程序。选择器会显示本地商品或其上游映射来源，方便管理员核对。根据转换程序的接口要求自行添加 `extra` 字段，可配置常量和受限变量，例如 `&#123;&#123;site.domain&#125;&#125;`、`&#123;&#123;product.title&#125;&#125;`。邮箱、手机号等个人信息默认不会传递。

转换请求的 JSON 主体顶层只有订单号 `order_no`、上游卡密列表 `items` 和 `extra`；订单号同时用于幂等。站点、商品、SKU 的字段不会自动附带，只有配置进 `extra` 的值才会发送。`extra` 的字段名由管理员依据转换程序的接口要求自行添加，不由 Zebra Store 固定。

### 编辑 `extra`

默认的**普通模式**可直接添加字段，按文本、数字、布尔值或 JSON 值编辑。文本字段可用“插入订单变量”追加 `&#123;&#123;变量路径&#125;&#125;` 占位符，例如 `&#123;&#123;order.order_no&#125;&#125;`。可选择订单号、数量、金额、站点域名与名称、商品 ID 与名称、SKU ID 与规格，以及实际采购上游的 ID、名称和协议。占位符保存在商品绑定中，实际交付时才用该订单的数据替换；含引号等字符的替换值仍作为 JSON 字符串安全序列化。

点**高级 JSON**可以直接编辑完整的 `extra` 对象，例如：

```json
{
  "provider": "p2",
  "merchant_order": "{{order.order_no}}",
  "notify": true
}
```

最外层必须是 JSON 对象，字符串中的占位符必须放在引号内。JSON 格式错误时会保留当前编辑内容，但不能切回普通模式或保存。格式正确后切回普通模式，表单会同步显示所有顶层字段；嵌套对象和数组显示为可编辑的 JSON 字段。保存前还会检查 JSON 结构、条件规则和变量路径。

### 条件规则

字段类型选择“条件规则”后，可点击添加多条“如果”条件，选择来源名称、订单数量或卡密等变量，再选等于、大小比较或正则匹配。每条条件的输出可以是固定值或变量；最下方配置“否则输出”。按从上到下的顺序，第一条命中即生效。卡密正则要求本批所有卡密都匹配。切换到高级 JSON 编辑后再回来，规则仍可在表单中继续修改。规则只保存在 Store，实际请求中的 `extra` 是求值后的普通 JSON。

仅当转换程序是 AI Top-up 时，在 `extra.category` 中填写套餐类型，在 `extra.provider` 中填写 `p1` 或 `p2`；也可以给 `provider` 设置来源名称或卡密格式条件。Zebra Store 不解析这两个值。已有绑定也需补全这两个字段，新转换请求才会被 AI Top-up 接受。

商品只要配置了绑定，自动发货和上游自动卡密交付就会先调用转换器；未配置的商品走原有交付流程。管理员手动发货时，如果输入的是逐行卡密且数量与订单一致，也会调用转换器；上游返回的人工处理说明不会被当作卡密转换。手动导入卡密不需要标注来源。转换结果是买家页面、下游供货接口、邮件和 Webhook 共用的正式交付内容。

## 失败与恢复

转换器调用失败时，订单保持处理中，不会把上游卡密交给买家。上游采购已经成功时，系统会保存其原始交付供内部重试，后续只重试转换，不会再次向上游采购。本地库存商品会固定本次使用的卡密；重试不会再扣另一批库存。

健康任务每分钟检查启用中的转换器。连续探测失败达到阈值会记录事件并通知管理员 Telegram；恢复时会记录恢复事件并唤醒挂起转换。全部卡密转换成功后，系统才完成订单并通知买家。类型错误、幂等冲突或修复配置后仍失败的订单，可在采购单页面使用“重试卡密转换”，此操作不会重新采购。后台首页会显示异常转换器名称、最近错误和影响商品数；转换事件日志不记录 Token 或卡密明文。

协议、健康探测和订单恢复的开发细节见[协议文档](./card-converter-protocol)。

若从旧请求结构升级，需同时更新 Zebra Store 和转换程序，并先核对待转换订单；旧结构产生的幂等记录可能与新请求内容不一致，不能直接按新结构重放。
