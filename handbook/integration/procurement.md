# 采购单与故障处理

作为下游，每卖出一件对接商品就会产生一张**采购单**。大多数时候它会自动完成，这一页讲出问题时怎么处理。

## 正常流程

```text
买家付款 ─► 待提交 ─► 已接受 ─► 已完成（卡密交给买家）
```

- 同步交付的协议（异次元、萌次元、Zebra Store 的自动发货商品）：几秒内直接到“已完成”；
- 异步交付的上游：先“已接受”，等上游回调或本站定时查询后变为“已完成”。

## 出问题时

| 情况 | 采购单状态 | 系统会做什么 | 你要做什么 |
|---|---|---|---|
| 你在上游的**余额不足** | 已拒绝 | 不自动重试 | 去上游充值，然后在采购单上点 **重试** |
| 上游**缺货** / 商品下架 | 已拒绝 | 不自动重试；下次同步时本站商品显示售罄 | 给买家**退款**（订单管理 → 退款），或等上游补货后重试 |
| 上游临时出错（5xx、限流） | 失败 | 按连接的重试次数和间隔自动重试 | 通常不用管；重试次数用完后手动重试 |
| **网络错误**，请求发出后没收到结果 | **待人工核对** | **不会**自动重试，**不会**自动退款 | 见下文 |
| 凭证错误 / 被停用 | 已拒绝 | 不自动重试 | 检查连接的 Key / Secret，联系上游 |
| 上游的**人工发货**商品 | 已接受 | 等待 | 上游发货后，按上游给的内容在本站订单里人工发货 |

::: tip 开启“下单前检查库存”
**系统设置 → 站点设置 → 上游同步** 打开“下单前检查库存”后，买家下单时会先问一次上游库存，
上游缺货就不让买家付款，能避免大部分“已付款却买不到”的情况。
:::

## 待人工核对：最需要小心的情况

请求已经发给上游，但是连接断了或超时，本站**不知道上游有没有成交**。上游可能已经扣了你的余额。
所以系统不会自动再买一次（可能重复购买），也不会自动退款给买家（可能货已经买到了）。

处理步骤：

1. 打开采购单详情，记下**本站订单号**和**追踪 ID**；
2. 登录上游站点，在你的订单记录里查找对应订单（Zebra Store 可以按下游订单号查；异次元按请求号）；
3. 分两种情况：
   - **上游已成交**：点 **重试**。重试使用同一个请求号，上游会识别为同一单，返回原来的卡密，**不会**重复扣款；
   - **上游没有这单**：点 **重试** 重新提交；或者点 **取消**，然后给买家退款。

## 重试和取消

- **重试**：用同一个请求号再提交一次，适用于所有失败、已拒绝、待人工核对的采购单；
- **取消**：采购单标记为失败，本站订单回退，你需要自己给买家退款（**订单管理 → 退款**）。

## 对账

定期到 **对接管理 → 对账中心** 新建对账任务，核对本站采购单和上游订单的状态、金额是否一致，
发现不一致逐条处理并标记。见 [对接管理 → 对账中心](/admin/integration#对账中心)。
