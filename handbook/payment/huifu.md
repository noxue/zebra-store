# 汇付：支付宝、微信 H5 / PC 收款

Zebra Store 通过汇付托管支付页面支持 **支付宝和微信 H5 / PC 收款**。支持支付下单、主动查单、RSA-SHA256 回调验签、原路退款、退款查询，以及这两类收款的交易对账单查询与下载；不包含汇付的进件、分账、结算、提现等其他产品接口。

- Rust SDK：[github.com/noxue/huifu-pay](https://github.com/noxue/huifu-pay)
- crates.io：[`huifu-pay`](https://crates.io/crates/huifu-pay)
- 汇付注册与申请入口：[使用 Zebra Store 邀请链接注册](https://paas.huifu.com/login?inviteCode=TAXG4QKSR)
- 汇付开发文档：[paas.huifu.com/docs/devtools](https://paas.huifu.com/docs/devtools/#/skillsv1_0)

## 个人申请资料

个人申请时先准备：

- 姓名；
- 手机号；
- 邮箱；
- 本人银行卡正反面照片；
- 本人身份证正反面照片。

先通过[Zebra Store 邀请链接](https://paas.huifu.com/login?inviteCode=TAXG4QKSR)注册汇付账号，再提交上述资料。直接联系汇付官网上的微信客服，或加入官网提供的微信群申请，通常会更快。审核通过后申请托管支付项目，并取得系统号、产品号、汇付商户号和 RSA 密钥。实际准入、费率、结算周期或补充材料以汇付审核结果为准。身份证、银行卡和私钥不要发到 GitHub Issue，也不要放进代码仓库。

## 新建支付渠道

进入 **支付管理 → 支付渠道 → 新建渠道**：

选择“汇付斗拱”后，表单会显示个人申请材料说明和汇付官网入口。系统会按当前站点域名自动填写 API 地址、项目名称、异步通知地址与支付回跳地址；Skill Source 固定为 `hfps/1.3.5`，无需填写。保存前请确认浏览器地址就是买家实际访问的公开域名，使用内网地址或后台专用域名时应手动改成商城域名。

| 字段 | 填写内容 |
|---|---|
| 支付提供方 | `汇付斗拱` |
| 支付方式 | 支付宝或微信；需要两个入口时分别建两个渠道 |
| 交互方式 | `二维码`（默认；PC 页内展示收款码，移动端调起汇付托管支付）；也可选择 `跳转`（PC 和移动端均跳转到汇付收银台） |
| API 地址 | 生产环境 `https://api.huifu.com` |
| 系统号 | 汇付提供的 `sys_id` |
| 产品号 | 汇付提供的 `product_id` |
| 汇付商户号 | `huifu_id` |
| Skill Source | 系统固定使用 `hfps/1.3.5`，无需填写 |
| 托管项目 ID | 在汇付合作伙伴控台单独创建 H5/PC 支付托管项目后取得；不在密钥管理页中，也不是产品号 |
| 托管项目名称 | 自定义名称，例如 `Zebra Store` |
| 商户 RSA 私钥 | 请求签名私钥，支持 PEM 或 Base64 |
| 汇付 RSA 公钥 | 响应和交易通知验签公钥 |
| 异步通知地址 | `https://你的域名/api/v1/payments/callback` |
| 支付完成回跳地址 | `https://你的域名/pay` |

保存时私钥会加密存储，重新打开只显示掩码。不要把生产私钥写进配置示例、日志或截图。

API 地址、Skill Source、项目名称和两个回调地址有默认值；系统号、产品号、商户号与两项 RSA 密钥从汇付开发者密钥管理页取得。H5/PC 托管项目 ID 需要在合作伙伴控台另行创建对应的支付托管项目后取得，因此不一定会出现在密钥管理页。不要把产品号 `product_id` 填入托管项目 ID。系统不会猜测密钥、商户身份或托管项目 ID。

## 支付和回调

支付宝使用汇付 `A_NATIVE` 托管模式，微信使用 `T_JSAPI` 托管模式。创建汇付渠道时可以选择两种交互方式：

- **二维码（默认，页内支付）**：桌面浏览器在 Zebra Store 支付页直接把汇付签名的 `jump_url` 显示成付款二维码，不自动离开当前页面；手机浏览器直接打开同一个汇付托管链接，由汇付按支付宝或微信渠道调起相应支付流程。
- **跳转**：桌面端和移动端都直接打开汇付托管收银台。

若浏览器或系统拦截应用唤起，页面仍保留“打开支付页面”和复制链接作为后备方式。

二维码承载的是汇付签名托管链接，不是 Zebra Store 自行拼装的支付宝或微信原生支付参数。这样无需额外收集支付宝 `buyer_id` 或微信公众号 `sub_openid`，也能保持现有验签通知、主动查单和退款闭环。

## 通道权限与商品品类

页内二维码仍属于汇付支付托管流程，商户需先开通支付托管功能以及对应的支付宝、微信收款权限。公开接入资料没有要求“只因在 PC 页内展示二维码”就额外选择一个固定商品品类，但实际销售内容、订单商品描述和申请时提交的经营范围必须一致。Zebra Store 会把真实订单标题写入汇付 `goods_desc`，请勿用于跨类目经营、虚假交易或渠道禁止/限制的商品。

微信、支付宝和汇付仍可能按商户主体、经营场景和商品类别补充审核或限制通道。例如汇付公开说明中提到，珠宝玉石、3C 数码在线销售配送、预售商品等部分微信小程序场景可能要求微信直连商户号，不能使用间连商户号。是否可用以汇付与支付渠道最终审核为准；申请前可把网站地址、实际商品示例和经营方式发给汇付客服确认。

参考：[汇付支付托管 JavaScript SDK 说明](https://paas.huifu.com/bbs/topic/28/%E6%B1%87%E4%BB%98%E6%94%AF%E4%BB%98%E6%96%97%E6%8B%B1%E6%94%B6%E9%93%B6%E5%8F%B0-javascript-%E8%AF%AD%E8%A8%80-sdk-dg-js-sdk)、[汇付风险常见问题](https://paas.huifu.com/bbs/topic/44/faq-%E9%A3%8E%E9%99%A9%E5%B8%B8%E8%A7%81%E9%97%AE%E9%A2%98%E5%8F%8A%E6%8A%A5%E9%94%99)。

汇付会向通知地址 POST `sign` 和原始 `resp_data`。Zebra Store 先对原始 `resp_data` 做 RSA-SHA256 验签，再校验商户号、订单号、金额和币种；成功落库后返回 `RECV_ORD_ID_订单请求号`。前端回跳只能用于改善体验，不能作为支付成功依据。

## 原路退款

后台接口 `POST /api/v1/admin/orders/{id}/original-refund` 使用原成功支付记录发起汇付原路退款。请求体与手动退款一致：

```json
{
  "amount": "1.00",
  "remark": "用户申请退款",
  "payment_fee_refunded": false
}
```

汇付已经返回最终成功时，Zebra Store 才创建本地退款记录并更新订单；返回处理中时，接口只返回网关退款状态，不会提前把订单标成已退款。

## 下载交易对账单

汇付渠道保存后，在 **支付管理 → 支付渠道** 找到该渠道，点击 **交易账单**：

1. 选择“文件生成日期”，通常是交易日期的次日；
2. 点击“查询账单”，查看文件生成任务状态；
3. 文件出现后点击“下载”。

Zebra Store 固定查询 `TRADE_BILL`，用于核对本库支持的支付宝、微信收款。汇付按 T+1/D+1 生成文件，建议中午后查询，并控制在每天三次以内。状态 `I/P/DP/FP` 表示仍在处理，`F` 表示失败，`S` 表示任务成功；`S` 且没有文件通常表示前一日没有交易。

下载地址是短时签名凭据。Zebra Store 会在服务端重新查询文件、校验汇付响应签名后代理下载，生产环境只接受 HTTPS、不跟随重定向，并限制账单大小。现有 **对接管理 → 对账中心** 用于采购订单与上游供货站对账，和支付渠道交易账单是两项不同功能。

## 上线前验证

1. 先用汇付官方本地沙箱验证支付宝、微信、查单、退款、退款查询、账单查询和下载；
2. 在生产环境分别创建支付宝和微信渠道；
3. 各用最小金额真实支付一笔；
4. 确认支付记录变为成功、订单自动发货、汇付后台金额一致；
5. 对测试订单发起原路退款并核对到账。

项目内置了可选的端到端沙箱测试 `huifu_sandbox_e2e`。它会通过真实 Zebra Store 路由创建游客商品订单，请求汇付托管支付，让沙箱主动发送 RSA Notify，重复投递同一通知，再验证数据库只结算一次并完成卡密发货。该测试默认忽略，只有在本机单独启动官方沙箱并提供沙箱环境变量时才运行。

::: warning 最终状态
汇付的 `resp_code` 表示请求是否受理。支付与退款的最终结果以验签通知或主动查询的 `trans_stat` 为准。
:::
