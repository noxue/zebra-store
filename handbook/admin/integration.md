# 对接管理

## 用途

和其他发卡站点对接：从上游进货（连接管理、商品映射、采购单、对账），以及审核下游的 API 凭证。
概念和每种协议的完整步骤见 [站点对接](/integration/)，这一页按后台页面逐个说明字段。

## 入口

左侧菜单 **对接管理**：连接管理、商品映射、采购单管理、对账中心、API 凭证。

## 连接管理

一个“连接”就是你在某个上游站点的进货账号。

![连接管理](/screenshots/admin/site-connections.png)

**新建连接**

![新建连接](/screenshots/admin/site-connection-edit.png)

1. **一键接入（仅 Zebra Store 协议）**：粘贴上游给你的连接码，点 **解析**，地址、Key、Secret 自动填好并立即测试连接；
2. 或者手动填写：

| 字段 | 说明 |
|---|---|
| 名称 | 自己起的名字，例如“异次元货源” |
| 对接协议 | **Zebra Store**（推荐，对方也是斑马小铺时）、**dujiao-next**、**异次元发卡**、**萌次元商城**。不同协议要填的字段不同 |
| 站点地址 | 上游的网址，例如 `https://supplier.example.com` |
| API Key / Secret | dujiao-next 和 Zebra Store 协议：上游个人中心“API 对接”里的凭证 |
| 商户 ID / 对接密钥 | 异次元协议：你在上游的用户 ID 和 app_key |
| API-ID / API 密钥 | 萌次元协议：你在上游的 API-ID 和密钥 |
| 供货站结算货币 | 异次元 / 萌次元协议需要手动填写，例如 CNY |
| 回调地址 | 上游发货后通知本站的地址。握手成功后会给出建议值，点 **应用** 即可 |
| 汇率 | 上游价格 × 汇率 = 本站的基础价格。同币种填 1 |
| 加价百分比 | 在基础价格上再加多少作为售价，例如 20 |
| 取整方式 | 不取整 / 向上取整到元 / 向上取整到角 |
| 自动同步价格 | 上游改价后是否自动更新本站售价 |
| 重试次数 / 重试间隔 | 采购失败后自动重试的次数和间隔（秒，逗号分隔） |

3. 点 **测试连接**：成功时显示上游站点名、结算货币、你在上游的余额、协议版本、支持的能力和建议汇率。

**列表操作**：编辑、删除、测试（Ping）、启用 / 停用、**重新应用加价**（修改加价比例后，把新规则应用到已导入的所有商品）。
列表里还会显示结算货币、同步方式（增量 / 全量）和推送状态。

## 商品映射

把上游的商品导入成本站商品。

![商品映射](/screenshots/admin/product-mappings.png)

**导入**：点 **导入商品** → 选择连接 → 按列表或按分类浏览上游商品 → 勾选商品（可以展开看规格）→ 选择本站分类 → 导入。
也可以**整个分类导入**，并选择是否自动在本站创建同名分类。

- 导入后的商品**默认下架**，检查价格和描述后再上架；
- 上游没有价格的规格不会被导入；
- 每行可以展开看规格对比：本站价格、上游价格、成本价、差价、上游库存、上游是否可售。

**操作**：同步（立即从上游拉取最新价格和库存）、启用 / 停用、删除，都支持批量。

**同步频率**：默认每 5 分钟同步一次（**系统设置 → 站点设置 → 上游同步** 可改）。
Zebra Store 协议的连接支持实时推送，上游一有变化立即同步。

## 采购单管理

买家买了对接商品并付款后，系统自动向上游下一张**采购单**。

![采购单管理](/screenshots/admin/procurement-orders.png)

| 状态 | 意思 |
|---|---|
| 待提交 | 排队中，马上会提交给上游 |
| 已接受 | 上游已收单，等待上游发货 |
| 已完成 | 上游已发货，卡密已经交给买家 |
| 已拒绝 | 上游明确拒绝（例如余额不足、缺货），不会自动重试 |
| 失败 | 暂时性错误（例如网络问题），会按连接的重试设置自动重试 |
| 待人工核对 | 不确定上游有没有成交（例如请求发出后网络断了）。**上游可能已经扣了你的钱**，系统不会自动重试或退款 |
| 已取消 / 已退款 / 部分退款 | |

- 顶部统计卡片可以点击，快速筛选对应状态；
- **重试**：用同一个请求号重新提交（上游会识别为同一单，不会重复购买）；
- **取消**：标记为失败并回退本站订单，之后你需要给买家退款；
- **详情**：上游订单号、成本与利润、追踪 ID、下次重试时间、时间线、上游退款记录，以及下载上游原始返回内容。

遇到失败怎么处理，见 [采购单与故障处理](/integration/procurement)。

## 对账中心

定期核对本站采购单和上游订单是否一致。第一次进入前需要完成合规确认。

1. **新建对账**：选择连接、类型（状态 / 金额 / 全部）、时间范围；
2. 任务完成后显示总数、一致数、不一致数；
3. 打开详情查看每一条不一致（本站状态 vs 上游状态、金额），处理后点 **标记已处理** 并写备注。

![对账中心](/screenshots/admin/reconciliation.png)

## API 凭证

下游站点（从你这里进货的人）在前台个人中心申请的凭证，在这里审核。

![API 凭证审核](/screenshots/admin/api-credentials.png)

- **通过**：用户获得 API Key 和 Secret；
- **驳回**：填写原因，用户可以修改后重新申请；
- **启用 / 停用**：停用后该凭证的所有对接请求立即被拒绝；
- **删除**。

::: warning 重新审核会换 Key
对一个已通过的凭证重新执行“通过”，会生成新的 API Key，并使该用户的异次元 / 萌次元兼容密钥失效，对方需要重新配置。
:::
